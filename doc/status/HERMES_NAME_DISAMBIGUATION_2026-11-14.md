# Status — Hermes 이름 구분 (2026-11-14)

_작성: 메스 (Hermes Agent) · 확정: 사람_
_관련: ADR-HERMES-000 · HERMES_PHASE0_BOUNDARY_LOCK_2026-10-09 · HERMES_PHASE1_PLAN_2026-10-23_

## 왜 이 문서가 필요한가

같은 이름 **"Hermes"** 가 두 층에서 쓰이고 있다. 구분하지 않으면 이 문서들을 읽는 사람(또는 다른 AI)이
현재 구현을 ADR-HERMES-000 경계 위반으로 잘못 판정한다.

## 두 개의 "Hermes"

| | 이름 | 정체 | 위치 | 실행 |
|---|---|---|---|---|
| **A** | **Hermes** (ADR·Phase 문서가 쓰는 이름) | 하준아이 앱 안의 **판단·제안 모듈** | `hajuncore-app` `lib/hermesRule.ts` · chat wire `lib/hajunApiPost.ts` | **금지** — ADR-HERMES-000 경계 그대로 |
| **B** | **메스** (= Hermes Agent) | 이 PC에서 도는 **실행 도구**. 사람이 파일·프로그램 작업을 맡기는 쪽 | `hermes serve` (127.0.0.1:9119) · `hajuncore-app` `lib/hermesClient.ts` · `app/api/hermes/route.ts` | **사람이 시킬 때만** 실행 |

## 이 문서가 하지 않는 것

- ADR-HERMES-000 **본문 수정 없음.** Phase 0 잠금(3조건 · 5후보 · 보류 정상 · 실행 금지)은 그대로 유효하다.
- Phase 1 범위 변경 없음. "제안이 사람에게 보이고, 사람이 승인한 뒤에만 기존 Core 경로로 실행"도 그대로다.
- 새 후보·새 Phase·패턴화·스킬화 없음.

## 경계가 걸리는 대상 (명확히)

- ADR-HERMES-000의 "실행 금지"와 Phase 1 Out 의 **"'실행 Agent'로의 Hermes 재정의 금지"는 A에 걸린다.**
  A는 지금도 DB write / synthesize / post_message 를 직접 호출하지 않는다.
- **B(메스)는 다른 층이다.** A의 실행 주체가 아니고, A가 고른 후보를 대신 실행하지도 않는다.
- A의 제안 면(「Hermes 제안 · 실행 아님」 블록)과 B의 실행 경로(「메스:」 · 「메스에게 실행」)는
  화면에서도 문구·상태가 분리돼 있다. 제안과 실행이 섞이지 않는다.

## B(메스) 쪽 현재 상태 (2026-11-13~14 실측)

| 항목 | 값 |
|---|---|
| 통로 | 하준아이 화면 → `/api/hermes` → `127.0.0.1:9119` → 이 PC의 메스 |
| 트리거 | 사람이 직접 — 「메스:」 접두어 또는 「메스에게 실행」 버튼. **자동 실행 없음** |
| 범위 | **로컬 전용.** 배포본(Vercel)에는 9119가 없다 — 버튼을 렌더하지 않고, 「메스:」는 사유를 명시한 오류를 반환한다 |
| 세션 | `session_id` 를 브라우저 localStorage 에만 보관. DB write 없음 |

| 모델 | 세션별 고정(kilocode `kilo-auto/free`). 사용자 데스크톱 세션의 모델은 건드리지 않는다 |
