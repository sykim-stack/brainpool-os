## 한 문장 목표

**Phase 1은 “제안이 사람에게 보이고, 사람이 승인한 뒤에만 기존 Core 경로로 실행”까지다. Hermes 자체는 여전히 실행하지 않는다.**

---

## 0. 고정 전제 (Phase 0에서 잠긴 것 · 유지)

| 항목 | Phase 1에서도 |
|------|----------------|
| Action Unit = 변화 ∧ 필요 ∧ 방향 | 유지 |
| 후보 5개만 | **확장 금지** |
| Hermes = 판단·제안 (2단계) | 유지 |
| 실행 = 사람 승인 후 | 유지 (ADR-CONFIRM-000과 정렬) |
| 보류 = 정상 | 유지 |

Phase 1은 ADR-HERMES-000을 **개정하지 않는다**.  
“자동 실행 / 후보 확장 / 패턴·스킬화”는 Phase 1 Out이다.

## 2. In / Out

### In (Phase 1에서 한다)

1. **제안 면 (Human-facing propose)**  
   - chat UI(또는 개발 패널)에서 `hermes` 후보·primary를 사람이 읽을 수 있게 한다.  
   - 문장은 “제안” 톤만. 자동으로 남기거나 이해를 바꾸지 않는다.

2. **승인 게이트 (Approve → 기존 경로)**  
   - 사람이 후보를 고르고 승인한 뒤에만 실행한다.  
   - 실행 주체는 Hermes가 아니라 **이미 있는 Core/Hajun 경로**:  
     - 남김 → `post_message` (마당에 남기기)  
     - 이해 갱신 → `synthesize_context` / 이해 갱신 흐름 (사람 확인 후)  
     - 확인 질문 → 사람이 질문을 보내거나, UI가 질문 초안만 채움  
     - 연결 → 참조 칩/ref 제안 (자동 링크 금지 권장)  
     - 보류 → 아무 것도 하지 않음  
   - ADR-CONFIRM-000: AI 채택 ≠ 사람 확정. 승인 = 사람 확정.

3. **관측·회귀**  
   - Phase 0 6케이스 회귀 유지.  
   - 승인 경로 smoke (남김 1건 등)는 **통합/수동**으로 가능하면 추가.  
   - 판정 결과 로깅은 최소(traceId 연계) — PII·원문 과다 저장 금지.

4. **규칙 품질 (후보 수 고정)**  
   - 신호 오탐/미탐 보정은 허용.  
   - 새 행동 후보 추가 금지.

### Out (Phase 1에서 하지 않는다)

- Hermes가 직접 DB write / synthesize / post_message 호출
- 자동 승인, 타임아웃 후 자동 실행
- 후보 목록 확장, 패턴화, 스킬화, 재사용 엔진
- 상품 마당 Hermes 적용 (별도 ADR/Phase 없이 금지)
- “실행 Agent”로의 Hermes 재정의

## 3. 작업 패키지 (권장 순서)

### P1-A. 제안 면 (UI)

- **산출**: chat 응답의 `hermes`를 사람이 보는 블록/칩  
- **수용**: AU 있을 때만 노출 가능, 보류만이면 숨기거나 “제안 없음”  
- **비수용**: 버튼 없이 자동으로 마당에 글이 생김

### P1-B. 승인 게이트 (1후보부터)

우선순위 제안:

1. **남김** — 승인 → 기존 “마당에 남기기” / `post_message`  
2. **확인 질문** — 승인 시 입력창에 질문 초안만 (전송은 사람)  
3. **이해 갱신** — 승인 시 synthesize 또는 “갱신할까요?” 확인 1회 더  
4. **연결** — ref/칩 제안만

한 번에 5후보 전부 자동화하지 않는다. **남김 + 확인 질문**부터.

### P1-C. 계약·문서

- 짧은 인터페이스 스케치 (요청/응답에 `hermes` + optional `approved_action`)  
- status 한 장으로 In/Out 재확인  
- ADR-HERMES-000 본문 수정 없음. 필요 시 “Phase 1은 승인 게이트만 추가” 주석성 status로 충분.

### P1-D. 검증

| 검증 | 방법 |
|------|------|
| 규칙 회귀 | `npm run test:hermes` (6+) |
| 제안 면 | UI에서 AU 유/무 표시 확인 |
| 승인→남김 | 승인 후에만 메시지 1건 생성 |
| 비승인 | 아무 write 없음 |
| Production | chat `hermes` 필드 유지, 실행 키 없음 |

열린 질문 (구현 전 결정):

1. 제안 면을 **본챗 UI**에 둘지, **개발/관제 패널**에만 둘지

## 6. 완료 정의 (Phase 1 Done)

다음이 **모두** 만족되면 Phase 1 완료로 기록한다.

1. 사람이 chat(또는 합의된 면)에서 Hermes 제안을 볼 수 있다.  
2. 최소 1개 후보(권장: 남김)는 **사람 승인 후에만** 기존 경로로 실행된다.  
3. 비승인·보류 시 write가 없다.  
4. `npm run test:hermes` 통과, Production `hermes` 필드 유지.  
5. Hermes 코드 경로에 자동 실행이 없다.
