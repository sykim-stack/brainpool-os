## 1. 문서 목적

이 문서는 하준AI의 두 핵심 기능인 **관제**와 **개발**을 하나의 공간 구조 안에서 정리한다. 하준AI는 단순한 대화창이나 특정 AI 모델의 인터페이스가 아니다. 하준AI는 브라이언풀의 메시지 세계를 읽고, 목적에 따라 서로 다른 공간 View를 제공하며, 필요한 방에 여러 AI가 참여하도록 연결하는 시스템이다.

이 문서는 다음 질문에 답한다.

> 하준AI에서 관제와 개발은 어떻게 분리되는가?  
> 엔진은 어떤 공간으로 표현되는가?  
> 메시지와 방·마당·AI·View는 어떤 관계를 가지는가?  
> AI에게 방의 맥락은 어떻게 전달되는가?

---

## 2. 핵심 정의

> **메시지가 세계의 원본이고, 공간은 그 세계를 바라보는 관점이다.**

브라이언풀에서 모든 콘텐츠는 메시지로 기록한다. 사용자의 질문, AI의 분석, 개발 결과, 관제의 검증, 사람의 결정, 오류, 작업 상태, 지식, 관찰은 모두 메시지다.

마당·거실·방·프로젝트·엔진·AI는 메시지를 소유하는 콘텐츠가 아니다. 이들은 메시지와 관계를 맺거나, 메시지를 특정 목적에 따라 필터링·정렬·해석·표현하는 공간 및 View다.

```text
Message World
     │
     ├── 관제 View
     │    └── 관제마당 · 거실 · 의미방
     │
     └── 개발 View
          └── 개발마당 · 거실 · 엔진방
```

## 3. 하준AI의 두 핵심 기능

하준AI에는 목적이 다른 두 개의 마당이 있다. 두 마당은 별개의 활동 영역이지만, **Neighbor**로 연결된다.

| 구분 | 관제마당 | 개발마당 |
| --- | --- | --- |
| 핵심 질문 | BRAINPOOL에서 무엇이 일어나고 있는가? | 무엇을 만들고 있으며 무엇을 검증하는가? |
| 공간 기준 | 의미·현상·전체 맥락 | 엔진·책임 영역 |
| 주요 활동 | 관찰·해석·상태 이해·결정 후보 확인 | 설계·구현·실험·오류 분석·테스트 |
| 기본 기록 | 정리된 상태·관찰·결정 후보 | 원본 개발 논의·AI 결과·작업 기록 |
| AI의 위치 | 의미를 해석하는 참여자 또는 관제 보조 | 엔진 작업에 참여하는 분석자·개발자 |
| 최종 결정 | 사람 하준 | 사람 하준 |

### 3.1 관제마당

관제마당은 엔진 목록을 보는 장소가 아니다. 여러 엔진에서 발생한 메시지를 통해 **브라이언풀에서 어떤 의미 있는 변화가 일어나고 있는지**를 바라보는 공간이다.

관제마당의 방은 처음부터 모두 확정되지 않는다. 실제 메시지와 활동이 축적되면서 반복되는 의미와 현상이 드러나면, 필요한 관제 View를 제안하고 승인하여 만든다.

```text
관제마당
├── 거실
├── 언어·의미
├── 대화·맥락
├── 이웃·연결
└── 이후 생태계에서 드러나는 새로운 의미 View
```

`언어·의미`, `대화·맥락`, `이웃·연결`은 하나의 엔진에 종속되지 않는다. 여러 엔진의 메시지가 하나의 의미 View에 함께 나타날 수 있다.

### 3.2 개발마당

개발마당은 개발자가 **무엇을 만들고 있는지**를 찾는 공간이다. 프로젝트의 엔진과 책임 영역을 기준으로 구성한다.

```text
개발마당
├── 거실
├── CoreChat
├── CoreRing
├── CoreHub
└── Hajun
```

개발마당의 방은 엔진 자체의 개발·오류·테스트·작업 메시지를 보여준다. **AI 모델의 이름은 방 이름이 아니다.** Llama, Nemotron, Codestral, DeepSeek, Gemini 등은 엔진방에 필요에 따라 참여하는 **교체 가능한 지능**이다.

## 4. 공간 계층

```text
하준AI 광장
│
├── 관제마당
│   ├── 거실 View
│   └── 의미 기반 방·View
│
└── 개발마당
    ├── 거실 View
    └── 엔진 기반 방
```

### 4.1 하준AI 광장

관제마당과 개발마당을 발견·이동하는 상위 View다. 별도의 콘텐츠 저장소가 아니다.

### 4.2 마당

활동 목적에 따라 메시지를 보여주는 상위 View다. 관제마당과 개발마당은 상하가 아니라 **Neighbor 관계**다.

```text
관제마당 ←──── Neighbor ────→ 개발마당
```

필요한 Context와 관계를 공유할 수 있지만, 기록 목적과 활동 권한은 분리한다.  
(Neighbor 의미: ADR-NEIGHBOR-000 — 관계이지 권한 자동 부여가 아님.)

### 4.3 거실

해당 마당에 속한 방들의 최신 활동을 발견하는 View다. **새 콘텐츠를 소유하지 않는다.** 방에 있는 메시지를 최신 시간·상태·관심 등으로 보여준다.

| 표시 정보 | 의미 |
| --- | --- |
| 방 이름 | 메시지가 관계된 방 |
| 최신 메시지 요약 | 최근 활동 발견용 |
| 마지막 활동 시간 | 최신성 |
| 참여 AI | 해당 활동 참여 AI |
| 상태 | 진행·검토·보류·결정 등 |
| 미확인 활동 수 | 확인 필요성 |

원본은 방에 있고, 거실은 Projection이다. **거실용으로 메시지를 복사해 별도 원본을 만들지 않는다.**

### 4.4 방

메시지와 특정 엔진·의미·작업 목적이 관계를 맺는 공간 View다. **방이 메시지를 소유하지 않는다.**

```text
방
├── 방의 정체성
├── 기본 책임
├── 선행 Context를 구성하는 메시지 집합
├── 최근 메시지
├── 참여 AI 관계
└── 메시지 View
```

## 5. 개발마당의 엔진방

| 엔진방 | 엔진의 본질 | 주요 개발 메시지 |
| --- | --- | --- |
| CoreChat | 흐름과 상호작용 | 대화 흐름, 연결, 세션, 상호작용, 오류 |
| CoreRing | 언어와 의미 | 번역, 언어 지식, 의미 분석, 패턴 |
| CoreHub | 연결과 운영 | Core 간 연결, 전달, 취합, 통합, 운영 |
| Hajun | 이해와 판단 | 전체 Context, 기억, 상태, 관제, AI 협업 |

구현 전 책임 기준이다. 파일·API·DB·Contract가 확인되지 않은 부분은 구현 사실로 취급하지 않는다.

### 5.1–5.4 요약

- **CoreChat:** 대화·상호작용 흐름
- **CoreRing:** 언어·의미·번역·패턴
- **CoreHub:** Core 간 연결·전달·취합 (실제 계약은 brainpool-os·레포 확인 후 확정)
- **Hajun:** 이해·기억·Context·관제 보조 · 개발마당에서는 Hajun 엔진 기능·Context 흐름 개발

## 6. 관제마당의 의미 View

엔진 이름이 아니라 관찰하고 싶은 **의미** 기준.

| 의미 View | 관련될 수 있는 엔진 |
| --- | --- |
| 언어·의미 | CoreRing, CoreChat, Hajun, CoreHub |
| 대화·맥락 | CoreChat, Hajun, CoreRing |
| 이웃·연결 | CoreHub, CoreNull, Hajun |
| 상태·기억 | Hajun, CoreHub, 각 Core 상태 메시지 |
| 이후 발견 | 실제 축적·관찰 후 제안 |

하나의 관제 View에 여러 엔진 메시지가 올 수 있고, 하나의 엔진 메시지가 여러 관제 View에 올 수 있다.

관제 방은 AI가 임의로 영구 생성하지 않는다. 반복 패턴이 확인되면 후보로 제안하고, **사람 승인 또는 명시된 운영 규칙**으로 생성한다.

## 7. 메시지 중심 원칙

### 7.1 메시지가 Source of Truth

사용자 질문, AI 분석, 개발 작업, 오류, 관제 검증, 결정 후보, 사람 결정, 상태 변화, 지식, 인수인계 — 모두 메시지로 기록할 수 있다.

### 7.2 View는 콘텐츠가 아니다

```text
메시지 = Source of Truth
View = 해석·필터·정렬·표현
```

새 화면·공간을 만들 때:

> 이것은 새로운 메시지인가, 아니면 기존 메시지를 다른 관계와 View로 보여주는 것인가?

### 7.3 메시지를 복사하지 않는다

개발 메시지가 관제에서 중요해도 복제하지 않고, 기존 메시지에 관제 View·관계·상태를 연결한다.

```text
하나의 메시지
├── 개발마당: 개발 작업
├── 관제마당: 결정 후보 View
├── CoreHub: 전달 대상
└── Hajun: Context 기준
```

## 8. 방 Context

임의 거대 텍스트 주입이 아니라, 방 정체성과 관계된 **메시지 집합**으로 Room Context Package를 구성한다.

```text
Room Context Package
├── 방 정체성 기준 메시지
├── 담당 엔진 책임 메시지
├── 선행 결정 · 관련 ADR
├── 최근 작업 · 오류 · 미해결
├── 현재 프로젝트 Context
└── 현재 질문
```

- **참여 AI:** 동일한 공통 작업 Context Package
- **관제 하준AI:** 작업 Context + BRAINPOOL 전체 맥락(필요 범위)

모든 MindWorld를 모든 참여 AI에게 주지 않는다. 최소 필요 Context, 민감·불필요 전체 맥락 제한.

---

## 9. AI 참여 구조

AI는 방의 소유자가 아니다. 방 책임을 수행하기 위해 참여하는 **메시지 작성 주체**다.

```text
방 Context Package
        ↓
참여 AI들 (교체 가능)
        ↓
각자의 독립 결과 메시지
        ↓
관제 하준AI 검증 메시지
        ↓
사람의 결정 메시지
```

모델 이름 ≠ 방 정체성. 특정 AI가 사라져도 방과 메시지 생명은 유지.

**관제 하준AI는 참여 AI와 동급의 랜덤 Judge가 아니다.** 결과와 전체 Context를 대조하고, 충돌·위험·불확실성·사람 결정 필요를 정리하는 **상위 관제 계층**이다.

```text
참여 AI → “나는 이렇게 분석한다.”
관제 하준AI → “각 AI 분석과 전체 맥락의 충돌·의미”
하준 → “이 방향으로 갈지 결정”
```

(제품 구현이 랜덤 Llama 심사이면 본 문서·DevChat 지시서 위반 — 수정 대상.)

## 10. 관제마당과 개발마당의 메시지 흐름

```text
개발마당 엔진방
  ├─ 질문 · AI 분석 · 코드·오류·테스트 · 작업 결정 후보
          ↓
개발 Context 정리
          ↓
관제마당 의미 View
          ↓
관제 하준AI 전체 맥락 검증
          ↓
하준의 의미·방향·최종 결정
```

Neighbor이므로 참조 가능. 개발 원본과 관제 정제 기록의 **목적은 구분**한다.

## 11. 정보 확실성 규칙

| 층위 | 의미 | 행동 |
| --- | --- | --- |
| Fact | 문서·레포·코드·사람 확정 | 설계 기준 |
| Inference | Fact에서 도출, 미명시 | 추론으로 표시 |
| Hypothesis | 미확인 가능성 | 확정 금지 |
| Verification Pending | 확인 필요 항목 | 확인 작업으로 전환 |
| Tentative Proposal | 검증 전 교체 가능 제안 | 승인·폐기 조건 명시 |
| Human Decision | 의미·방향·권한·영구 저장 | AI가 확정하지 않음 |

레포·문서를 읽기 전 테이블명·API·Core 존재·저장 책임을 **추정하지 않는다.**

## 12. 개발 단계의 범위 (최소 흐름)

1. 관제마당과 개발마당 구분
2. 각 마당 거실에서 방 목록·최신 메시지
3. 개발마당: CoreChat·CoreRing·CoreHub·Hajun 엔진방
4. 방 메시지 집합 → Room Context Package
5. 참여 AI에 동일 작업 Context
6. AI 원본 결과 메시지 보존
7. 관제 하준AI가 전체 Context로 검증
8. 관제 결과·사람 결정은 별도 메시지

관제 의미 View는 축적 후 필요한 것부터 제안. 처음부터 전부 확정하지 않는다.

사람 승인 전 DB·API·운영 권한·SoT 임의 변경 금지.

## 14. 최종 정의

> **하준AI는 메시지를 원본으로 하는 공간형 지능 시스템이다.**  
> 개발마당은 CoreChat·CoreRing·CoreHub·Hajun 등 **엔진 책임** 기준.  
> 관제마당은 엔진 이름이 아니라 **언어·의미·대화·맥락·이웃·연결** 등 의미 기준.  
> 두 마당은 Neighbor. 거실은 방의 최신 메시지 View. 방은 메시지를 소유하지 않고 관계를 맺는다.  
> AI는 방에 참여해 결과 메시지를 남긴다. 관제 하준AI는 전체 Context로 검증하고, 하준은 의미·방향·최종 결정을 담당한다.

목적은 특정 AI·화면 고정이 아니라, 메시지와 Context를 중심으로 공간과 지능을 **교체 가능**하게 유지하며 실제 사용·축적으로 성장하게 하는 것이다.

| 용어 | 정의 |
| --- | --- |
| Message | 기록되는 모든 콘텐츠의 원본 단위 |
| View | 메시지를 목적에 따라 보여주는 표현·필터·정렬 |
| 광장 | 관제·개발 마당을 발견·이동하는 상위 View |
| 마당 | 활동 목적에 따른 메시지 View |
| 거실 | 방의 최신 활동 Projection (복사 원본 아님) |
| 방 | 엔진 또는 의미와 메시지가 관계를 맺는 공간 View |
| 엔진방 | 개발마당에서 엔진 책임 기준 방 |
| 의미 View | 관제마당에서 현상·의미 기준 방 |
| Room Context Package | 방 정체성·관련 메시지로 만든 AI 작업 Context |
| 참여 AI | 결과 메시지를 남기는 교체 가능 지능 |
| 관제 하준AI | 전체 Context로 참여 결과를 해석·검증 |
| Neighbor | 연결되나 서로의 정체성·기록을 소유하지 않는 관계 |

## 부록 B. 구현하지 말아야 할 오해

```text
AI 이름으로 방을 만들지 않는다.
방이 메시지를 소유한다고 가정하지 않는다.
거실에 최신 콘텐츠를 복사해 별도 원본을 만들지 않는다.
관제 하준AI를 참여 AI와 동급 랜덤 Judge로 두지 않는다.
관제 의미 View를 처음부터 모두 확정하지 않는다.
확인되지 않은 DB·API·Core를 사실처럼 구현하지 않는다.
AI 분석 결과를 사람의 결정으로 승격하지 않는다.
```
