# ADR-SEED-ADAPTER-000: Seed Adapter 제거 트리거 조건

**기준일:** 2026-08-20  
**상태:** Draft — Phase 0  
**대상:** 클로3 (CoreNull)  
**대상 파일:** `lib/roomStage.js` (또는 동등 Adapter)  
**상위:** CoreNull_Core_Principles (Anchor), CORENULL_ROADMAP  
**충돌 시:** Anchor가 이긴다.

---

## 0. 이 문서가 결정하지 않는 것

- Seed 스위치 4컬럼(`seed_started_at`, `seed_target_date`, `has_participants`, `harvested`)의 **실제 마이그레이션 방법**
- `lib/roomStage.js`의 내부 구현/리팩터링
- Adapter 제거 **이후**의 코드 형태

이 문서는 **언제 제거할지 판단하는 기준**만 정한다.

---

## 1. 배경

`lib/roomStage.js`는 현재 데이터(`seed_mode` / `bloom_date`)를 Anchor §12에서 정의한 미래 계약(4개 스위치)으로 매핑하는 **과도기 계층**이다.

Adapter 자체는 정상이고 의도된 설계다. 문제는 **“언제 걷어낼 것인가”**가 정의되어 있지 않다는 것이다. 날짜로 정하면 실제 마이그레이션 준비와 무관하게 데드라인 압박이 생기고, 반대로 기준이 없으면 Adapter가 영구 기술 부채로 굳어진다.

---

## 2. 결정

**날짜가 아니라 트리거 조건으로 판단한다.**

```text
Seed Adapter 제거 시점 =
  미래 계약(스위치 컬럼)을 직접 사용하는 주체가 처음 생기는 순간
```

“주체가 생긴다”는 것은 다음 중 하나를 의미한다.

1. **CoreHub**가 스위치 컬럼을 직접 읽어야 하는 기능이 확정된다.  
   예: RingBlock 고도화가 실제로 `seed_started_at` 기반 정밀 계산을 요구하는 시점.  
   (현재 House 정적 데이터로 충분하면 **트리거 아님**.)

2. **CoreNull UI**가 `seed_mode`/`bloom_date`로 표현 불가능한 상태를 요구한다.  
   예: “참여자는 있지만 아직 씨드 스위치를 켜지 않은 방”처럼 `seed_mode: true` 하나로 구분 못 하는 경우.

3. **다른 Core**(HajunAI, CoreRing)가 `sync_snapshot` 등에서 스위치 스키마를 **직접 기대하는 계약**을 맺는다.

트리거가 발생하지 않는 한 Adapter는 **유지**한다.  
“언젠가 정리해야 할 것 같아서” 미리 마이그레이션하지 않는다.

### 2.1 트리거 판정 권한

조건 1~3은 해석이 필요하다. 클로3 단독으로 “이제 트리거다”고 확정하지 않는다.

1. 후보 트리거가 보이면 **이 문서 §4에 사실 기록** (몇 번 조건, 어떤 기능/커밋/요구인지)
2. **클로1(총괄) 확인·승인** 후 마이그레이션 ADR 착수  
   (Master_Prompt: ADR Approval ≈ Architecture + Planning)

기록만으로 마이그레이션을 시작하지 않는다.

### 2.2 감시 항목 (조건 2 · Neighbor)

조건 2 예시는 추상 미래만이 아니다. **ADR-NEIGHBOR-000 / Phase B 이웃 작업** 진행 중 Room·참여 상태가 더 세분될 수 있다.

- Neighbor·참여 관련 구현 중 `seed_mode`만으로 **표현 불가한 상태**가 나오는지 **주시**한다.
- 해당하면 §4에 기록하고 클로1 확인을 받는다.  
- “현재는 트리거 아님”을 영구 선언하지 말고, **Phase B 동안 감시**한다.

### 2.3 암묵적 드리프트

트리거는 “명시적 4컬럼 요구”만이 아니다. Adapter를 우회해 `seed_mode`를 **각자 다른 의미로** 해석하는 코드가 스며들면, 조건 1~3에 안 걸려도 부채가 된다.

- **Architecture Linter / PM Guard / 코드 리뷰**에 점검 항목 추가 권고:  
  `Room stage·seed 관련 신규 코드가 Adapter(`roomStage` 등)를 우회하는가?`
- 우회가 발견되면 트리거 후보로 §4에 기록한다.

---

## 3. 근거

1. **Evolution over Expansion** (Master_Prompt) — 실사용 요구 없는 마이그레이션은 확장이며 진화가 아니다.
2. **로드맵 Phase B** — 스위치 마이그레이션이 이미 대기 항목. 이 문서는 “언제(날짜)”를 **“무엇이 오면”**으로 바꾼다.
3. **Adapter는 경계이지, 조건 없는 방치만 부채다.** 트리거가 명시되어 있으면 유지 자체가 문제가 아니다.

---

## 4. 트리거 발생 시 절차

트리거 후보가 실제로 보이면:

1. **이 문서에 기록** — 조건 번호, 요구 기능, 발견 경로(PR/이슈/세션). 상태: `트리거 후보`
2. **클로1 확인·승인** — 승인 전에는 마이그레이션 ADR 본문 확정·실행 금지
3. **마이그레이션 범위 ADR 작성** (별도)  
   - 필요한 컬럼만 우선할지, 4개를 한 번에 할지 **선택지로 연다** (과설계 방지).  
   - `corenull_rooms` 변경 + 기존 데이터 backfill 방법
4. 마이그레이션 **완료 후** Adapter 로직 제거
5. 로드맵 Phase B 해당 항목 완료 처리

부분 마이그레이션(예: `harvested`만)이 트리거와 맞으면 전체를 강제하지 않는다. 나머지 컬럼은 이후 트리거에 맡긴다.

---

## 5. Validation Check (Anchor)

1. Message 없이 존재하는가? → Adapter는 Room 스위치 매핑이며 콘텐츠 기능 아님. 해당 없음.
2. 중복 로직인가? → 없음. 현재 필드와 미래 필드 이중 관리를 **막기 위한** 문서.
3. House Container 비즈니스 로직인가? → Adapter는 `lib/` 데이터 계약. House UI 로직 아님.
